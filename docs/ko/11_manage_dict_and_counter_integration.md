## 1. 사전 관리 시스템 (manage_dict.py) 구축

영어 사전의 파편화를 해결하고 신조어 및 오발음을 중앙 제어하기 위한 CLI 기반 사전 관리 시스템을 구축했습니다.

### 구조 및 데이터 흐름
```
[영어 소스 사전군]
 ├─ cmu.json (일반 영어 발음)
 ├─ brand.json (IT 브랜드/기술명)
 └─ custom.json (수동 교정)
         │
         ▼ (scripts/manage_dict.py build)
 ┌───────┴────────────────────────┐
 │   dict_eng_merged.json (병합)  │ ➔ 한국어 발음 전처리 시 1순위 참조
 ├────────────────────────────────┤
 │   dict_loanwords.json (역색인)  │ ➔ 외래어 판별 및 경음화 차단에 참조
 └────────────────────────────────┘
```

### 주요 기능
* **build**: 세 가지 소스 사전을 중복 제거 및 대소문자 매칭 우선순위를 기준으로 병합하여 `dict_eng_merged.json`을 생성하고, 동시에 한글 복원 역색인 사전인 `dict_loanwords.json`을 자동 빌드합니다.
* **check**: 소스 사전 간 동일 단어에 대한 발음 충돌(예: `Azure` ➔ cmu: 아주어, brand: 애저) 및 대소문자 중복 표기를 검출하여 사전의 무결성을 유지합니다.
* **search**: 특정 영어 단어 혹은 매칭된 한글 발음으로 사전을 양방향 검색할 수 있습니다.

## 2. 외래어 경음화 차단

외래어(영어 차용어) 내부의 자음(특히 'ㄹ' 받침 뒤)이 한국어 표준발음법 제26항(한자어 'ㄹ' 뒤 경음화)에 오적용되어 강하게 발음되던 문제를 차단했습니다.

### 차단 설계
1. **형태소 기반 차단**: 형태소 분석 태그가 외래어(`SL`)인 경우 경음화 대상에서 즉시 제외합니다.
2. **역색인 기반 차단**: `dict_loanwords.json`을 조회하여 한글 복원 텍스트가 영어 사전(역색인)에 존재하는 단어일 경우 외래어로 판정하여 경음화를 차단합니다.
   * *예시*: `'길드'` ➔ 기존 `'길뜨'`로 경음화되던 발음이 원래 외래어 발음인 **`'길드'`**로 정상 유지됩니다.
   * *예시*: `'스킬셋'` ➔ 기존 `'스킬섿/스킬쎋'`으로 발음되던 부분이 **`'스킬섿'`**으로 정상 유지됩니다.

## 3. 통합 카운터(Counter) 모델 개발 및 연동

기존에 숫자 + `'번'` 조합만 처리하던 Neural Head를 `'번'`, `'대'`, `'장'`, `'동'` 4대 단위를 모두 아우르는 **통합 카운터(Counter) 모델**로 전면 개편하였습니다.

### 데이터셋 구축 및 모델 재학습
* **통합 데이터셋**: DeepSeek API를 통해 수집 및 정제한 데이터와 기존 '번' 데이터를 병합하여 총 **2,575건**의 고품질 통합 의존명사 데이터셋(`unit_extracted.jsonl`)을 구축했습니다.
* **모델 훈련**: BERT Hidden State 특징을 재사용하는 구조로 재학습을 진행하여, 검증 세트에서 **98.5%의 분류 정확도**를 달성하고 `model_counter.onnx`로 내보냈습니다.

### E2E 파이프라인 연동 (`classifier.py`)
1. **명칭 변경**: 기존의 협소한 개념인 `beon`을 범용적인 `counter`로 변경했습니다.
   * `self.beon_session` ➔ `self.counter_session`
   * `result["beon"]` ➔ `result["counter"]`
2. **단위 확장 정규식**: `_run_counter` 메소드에서 `r'(\d+)(번|대|장|동)'` 패턴을 검출하여 문맥 분류 세션을 통과시킵니다.
3. **결과 결합 (Overwrite)**: `process()` 메소드 내에서 모델의 `counter` 분류 결과가 있을 때, 룰 기반 숫자 분류기인 `numbers` 결과값의 해당 라벨을 덮어쓰도록 설계하여 E2E 파이프라인이 모델의 예측을 최우선으로 따르도록 보장했습니다.

### 예외 규칙 보완
* **"번째" 룰 세분화**: `"번째"` 단위 수식어가 붙을 때, 고유어 수 표현의 한계(99)를 넘어가는 **100 이상일 때는 항상 `sino`** (예: "이백오십 번째", "천 번째")로 판정하고, **100 미만일 때만 `native`** (예: "스물한 번째")로 판정하도록 교정했습니다.
* **"제" 접두사 공백 허용**: `"제 5대 대통령"`과 같이 접두사 뒤에 공백이 있을 때도 `sino`로 올바르게 읽히도록 `before.rstrip().endswith("제")`로 파싱 방식을 개선했습니다.

## 4. 형태소 분석 사전 (morph_trie.pkl) 복구

로컬 환경 셋업 시 조사 `'의'` ➔ `'에'` 변환 등에 필요한 형태소 분석 사전(`morph_trie.pkl`)이 유실되었던 문제를 추적하여 복구했습니다.

* **원인**: 대용량 모델 가중치 제외를 위해 `.gitignore`에 `weights/` 디렉토리가 등록되어 있어, 형태소 사전 파일이 Git 저장소에 포함되지 않아 환경 복제 시 유실되었습니다.
* **조치**: 로컬에 존재하는 우리말샘 소스 압축파일과 MeCab 라이브러리를 바인딩하여 `build_morph_trie.py` 스크립트를 구동했고, 최종 **592,053건**의 Trie 구조를 담은 `morph_trie.pkl (12.7MB)` 파일을 성공적으로 복구 적재하였습니다.

> [!WARNING]
> **Silent Fallback(조용한 우회)의 함정**
> `classifier.py`의 구현 상 형태소 모델 관련 파일(`model_morph.onnx`, `model_label_morph.json`, `morph_trie.pkl`) 중 하나라도 유실되면, 예외(Exception)를 발생시키지 않고 로그창에 경고(`Warning: Morph is enabled but missing...`)만 남긴 채 **형태소 분석 엔진 작동을 완전히 건너뛰게(bypass) 설계**되어 있습니다.
> 이로 인해 형태소 분석 기반의 연음 법칙이나 조사 `'의'` 발음 보정이 전혀 동작하지 않아도 E2E 테스트 스크립트가 크래시 없이 조용히 통과되어 문제를 알아차리기 어렵습니다. 
> 
> **배포 및 환경 구축 시 주의사항**:
> 1. 신규 환경 구축 시 반드시 `weights/ko/morph_trie.pkl` 및 관련 ONNX 가중치가 완벽하게 배치되었는지 콘솔 경고를 확인해야 합니다.
> 2. `.gitignore`에 가중치 폴더가 통째로 제외되어 있으므로 배포 스크립트(또는 LFS)를 통해 명시적으로 사전 파일들을 함께 동기화해주어야 합니다.
