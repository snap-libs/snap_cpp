## 3. 에러 상세 분석

### 3.1. 안다 — 30건 (65.1%)

#### 에러 유형 분류

| 방향 | 건수 | 설명 |
|------|:----:|------|
| TENS→NONE | 13건 | 껴안다인데 알다로 예측 |
| NONE→TENS | 17건 | 알다인데 껴안다로 예측 |

#### 패턴 분석

**공통 구조**: 전부 `"~을/를 안다 + 동사"` 형태

```
TENS (껴안다):  "아이를 안다 재웠다"     → 목적어가 사람/동물
NONE (알다):    "사실을 안다 말했다"     → 목적어가 추상명사
```

하지만 BERT single-token 임베딩으로는 **목적어의 의미 차이**(사람 vs 추상개념)를 포착하기 어려움.

#### 대표 에러 케이스

**NONE→TENS (알다를 껴안다로 오분류)** — 고 confidence 에러:

| conf | 문장 | 실제 |
|:----:|------|:----:|
| 0.849 | "아이가 답을 **안다** 손을 들었다." | 알다 |
| 0.804 | "그녀는 진실을 **안다** 침묵했다." | 알다 |
| 0.775 | "그녀는 비밀을 **안다** 입을 다물었다." | 알다 |
| 0.719 | "그는 비밀번호를 **안다** 로그인했다." | 알다 |
| 0.708 | "그녀는 내 마음을 **안다** 다가왔다." | 알다 |

**TENS→NONE (껴안다를 알다로 오분류)** — 저 confidence:

| conf | 문장 | 실제 |
|:----:|------|:----:|
| 0.614 | "그녀는 내 고민을 **안다** 상담했다." | 껴안다 |
| 0.610 | "엄마가 두 아이를 **안다** 사진 찍었다." | 껴안다 |
| 0.599 | "아기가 엄마 품에 **안다** 웃었다." | 껴안다 |

> [!WARNING]
> **근본 원인**: "~을/를 안다"는 껴안다/알다 모두 동일한 문법 구조. BERT 단일 토큰 위치의 hidden state만으로는 목적어의 의미(사람 vs 추상개념)를 충분히 반영하지 못함. confidence도 0.50~0.85 범위로 모델 자체가 불확실.
>
> **해결하려면**: multi-token attention (목적어 정보 포함) 또는 형태소 분석기 결합 필요

## 6. 안다 — 근본적 어려움 및 향후 과제

### 6.1. 왜 안다는 어려운가

`안다`는 한국어에서 두 동사가 **완전히 동일한 문법 구조**를 공유한다:

```
[NP-를/을] + 안다 + [동사/어미]
  ↑
  알다(NONE)와 껴안다(TENS) 모두 이 구조
```

**목적어를 알아도 해결되지 않는 이유**:

| 문장 | 목적어 | 정답 | 모델 예측 | conf |
|------|--------|:----:|:---------:|:----:|
| "나는 그 사실을 이미 안다 말했다." | 사실(추상) | NONE | **TENS** | 0.688 |
| "그는 비밀번호를 안다 로그인했다." | 비밀번호(추상) | NONE | **TENS** | 0.929 |
| "그녀는 내 고민을 안다 상담했다." | 고민(추상) | TENS | NONE | 0.614 |

- `고민을 안다` → "고민을 껴안다(비유적)"도 실제 한국어에서 사용됨
- 목적어가 추상명사여도 두 의미 모두 성립하는 경우가 많음
- **사람/동물 명사**(`아이를`, `아기를`)만 TENS가 명확하나, 전체 에러의 소수

**confidence 분포 분석** (32건 에러):

| confidence 범위 | 건수 | 의미 |
|:--------------:|:----:|------|
| 0.90 이상 | 3건 | 모델이 완전히 확신하며 틀림 |
| 0.70~0.89 | 8건 | 높은 확신으로 틀림 |
| 0.60~0.69 | 12건 | 중간 확신으로 틀림 |
| 0.60 미만 | 9건 | 낮은 확신 (이미 default=NONE으로 fallback) |

> [!WARNING]
> **핵심 문제**: 에러 23건(72%)이 confidence ≥ 0.60인 **고확신 오분류**다.  
> 이미 `conf < 0.6` fallback=NONE 룰이 있으나, 대부분의 에러는 이를 통과함.  
> Threshold를 올리면 정상 케이스도 함께 default로 떨어져 전체 정확도 하락.

### 6.2. 시도했거나 검토한 방법들

| 방법 | 결론 |
|------|------|
| **목적어 hidden 추가 (span pooling)** | 목적어가 추상명사면 여전히 모호. 부분 개선 기대 가능하나 학습 데이터도 부족 |
| **형태소 분석기 결합** (사람 명사 판별) | 사람 명사는 TENS 확정 가능하나 전체 에러의 소수만 해당 |
| **default NONE 강제** | NONE→TENS 에러 23건 개선, TENS→NONE 에러 9건 악화. 순이익 작음 |
| **`안다`를 neural 대상에서 제거** | 이미 `conf < 0.6` fallback이 동일 역할을 함. 불필요 |
| **룰 추가** (`를 잡`, `을 잡` → NONE 등) | 맥락 의존적 패턴이 많아 false positive 리스크 큼 |

> [!NOTE]
> **현재 결론**: `안다`의 32건 에러는 한국어 자체의 구조적 모호성에서 비롯되며,  
> 현재 아키텍처(단일 토큰 BERT hidden + MLP)로는 해결에 한계가 있음.  
> **현재 정확도 92.2%를 유지하는 상태에서 향후 과제로 수용.**

### 6.3. 향후 과제 (우선도 순)

| 과제 | 복잡도 | 예상 효과 | 선행 조건 |
|------|:------:|:---------:|-----------|
| **사람/동물 명사 사전** + 목적어 룰 | 낮 | +5~8건 | 명사 분류 사전 구축 |
| **목적어 span hidden 포함** (MLP 입력 확장) | 중 | +8~15건 | 학습 데이터 확충 (\'안다\' 200건 이상) |

| **레이블 재검토** ("고민을 안다" 등 중의적 케이스) | 중 | 데이터 품질 향상 | 원어민 재검수 |
