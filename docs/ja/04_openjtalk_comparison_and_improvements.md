# 04. Morph Head 도입 후 일본어 G2P 개선 실험 보고서

이 문서는 BERT 형태소 분석 헤드(morph head) 도입 이후 일본어 G2P(Grapheme-to-Phoneme)
프론트엔드의 성능을 OpenJTalk와 비교 측정하고, 발견된 문제를 단계적으로 개선한 실험 전 과정을 기록합니다.

---

## 1. 개요 및 배경

*   **목적**: Morph head 도입 이후 SNAP 일본어 G2P의 실제 성능을 OpenJTalk 대비 정량 측정하고, 코드 품질 개선(리팩토링)과 사전 패치 확충을 병행하여 정확도를 향상.
*   **비교 대상**: OpenJTalk (OJT) — 공개 TTS 엔진, 일본어 G2P 업계 표준
*   **데이터셋**: Wikipedia 일본어 텍스트 기반 Gold 데이터셋 (OpenJTalk 변환 + 수동 검수)
*   **평가 방법**: 문장 단위 완전 일치. N=1000 무작위 샘플, 복수 seed 교차 검증
*   **벤치마크 스크립트**: `snap_py/scripts/compare_openjtalk.py`

### 카타카나 표기 규약

이 프로젝트는 표준 카타카나와 다른 정규화 표기를 사용합니다:

| 일반 표기 | 이 프로젝트 | 예시 |
|-----------|------------|------|
| ョウ (long o) | ヨオ | じょう → ジヨオ |
| ッ (촉음) | ツ | きっと → キツト |
| シャ | シヤ | しゃ → シヤ |
| を (조사) | オ | を → オ |

## 2. 기준선 측정 (seed=99)

### 목적
Morph head 도입 이후 현재 SNAP의 성능을 OpenJTalk와 비교하여 개선 기준점 확립.

### 결과 (N=1000, seed=99)

| 지표 | SNAP | OJT |
|------|------|-----|
| 정확도 | **62.7%** | **62.9%** |
| SNAP만 정답 | 6.4% | |
| OJT만 정답 | 6.6% | |
| 둘 다 정답 | 56.3% | |
| 둘 다 오답 | 30.7% | |
| SNAP/OJT 일치율 | 68.2% | |

### 분석
*   SNAP과 OJT가 거의 동점(0.2%p 차이), Morph head 도입 효과로 규칙 기반 대비 대폭 개선됨
*   불일치 케이스(31.8%)가 추가 개선 여지
*   `둘 다 오답` 30.7%는 Gold 기준 자체의 어려운 케이스 포함

## 3. Counter Liaison JSON화 (Phase B)

### 배경 및 문제점
일본어 수사 연음(렌다쿠/촉음화) 규칙이 Python과 C++에 각각 하드코딩되어 있어 동기화가 어렵고, C++에는 버그까지 존재:

```python
# 기존 phonology_ja.py: 63줄 if/elif 체인
elif num_surf == 'ジュウ' and unit_surf in (...):
    num_kata = num_kata[:-6] + 'ジッ'  # 버그: ジュッ이 맞음
```

### 해결책: weights/ja/ja_counter_liaison.json 신규 생성

자음군 분류(K/S/T/H), 촉음화(sokuon) 5규칙, 탁음/반탁음(daku/handaku) 및 예외 규칙을 단일 JSON으로 추출하여 Python과 C++이 공유.

### 구현 결과

| 항목 | Before | After |
|------|--------|-------|
| Python liaison 코드 | 63줄 하드코딩 | apply_liaison() 1줄 호출 |
| C++ liaison 코드 | 110줄 하드코딩 | apply_liaison() 2줄 호출 |
| Python/C++ 공유 데이터 | 없음 | ja_counter_liaison.json 공유 |
| C++ ジュウ 촉음화 | ジッ (오류) | ジュッ (수정) |

리그레션 없음: seed=99 정확도 유지 확인.

## 4. Dict Patches 통합 (Phase C-1)

### 배경: Drift 문제

```
ja_dict_patches.json : 919건  (C++/Python 공유)
phonology_ja.py      : 1050건 (Python 전용 _DICT_PATCHES)
차이                 :  131건이 Python에만 존재
```

Python에서만 효과를 보던 131건의 패치가 C++에는 적용되지 않는 상태.

### 작업 내용
1.  Python `_DICT_PATCHES`에서 JSON에 없는 131건 추출
2.  JSON과 충돌하는 5건 수동 해결 (洋服作り 깨진 값 폐기, 生育→セイク 단축형 통일 등)
3.  `ja_dict_patches.json`에 통합, Python `init_dicts()` 시 자동 로드

### 결과

| 항목 | 이전 | 이후 |
|------|------|------|
| ja_dict_patches.json | 919건 | 1050건 |
| Python-only drift | 131건 | 0건 |

## 5. 다중 Seed 교차 검증

### 목적
단일 seed(=99) 과적합 위험 방지. 다른 seed에서도 개선이 유지되는지 검증.

### 결과 비교

| Seed | SNAP | OJT | 대소 | 불일치 건수 |
|------|------|-----|------|-----------|
| 99 (기준) | 62.7% | 62.9% | +-0.2% | |
| 42 | 65.0% | 59.8% | SNAP +5.2% | 70건 |
| 7 (패치 전) | 56.8% | 61.2% | OJT +4.4% | 159건 |
| 7 (패치 후) | 57.9% | 61.2% | OJT +3.3% | 148건 |

### 핵심 관찰
*   **Seed별 편차 큼** (56.8%~65.0%, 8.2%p 범위): 1000건 샘플 문장 구성에 크게 의존
*   **seed=42에서 SNAP 우세** (+5.2%): 일반 명사·복합어 위주 문장이 많은 샘플
*   **seed=7에서 OJT 우세** (+4.4%): 훈독/음독 경계, 고유명사, 특수 동사 형태가 많은 샘플

### 구현 방식 3가지 병행

**(1) `ja_dict_patches.json`에 직접 추가** (JSON 레벨, 총 1069건으로 확장)

**(2) `phonology_ja.py` Phase 4-0h 텍스트 치환 추가**
BERT 형태소 분석이 덮어쓰는 경우를 대비, kanji→hiragana 선제 치환:
```python
text = text.replace('避難者', 'ひなんしゃ')   # 者→もの 방지
text = text.replace('重篤', 'じゅうとく')     # 人名読み 방지
text = text.replace('日本一', 'にっぽんいち') # にほんいち 방지
# ... (19개)
```

**(3) 카타카나 레벨 보정** (Phase 4 post-processing)
BERT가 잘못된 카타카나를 출력한 경우 직접 치환:
```python
text = text.replace('イタダキジヨオ', 'チヨオジヨオ')  # 頂上
text = text.replace('ウミジヨオ', 'カイジヨオ')         # 海上
text = text.replace('ダイリク', 'タイリク')              # 大陸
```
