## 2. 처리 속도 평가 결과 (1,000문장, ms/문장)

VITS 구동 환경을 반영하여, BERT hidden state 연산 시간과 순수 프론트엔드 변환 속도를 분리 계측했습니다.

| 엔진 | 평균 속도 | 중앙값 (Median) | 편차 | 30ms 초과 비율 (Spike) |
|:---|---:|---:|---:|---:|
| **SNAP (전체)** | **32.64 ms** | **-** | **-** | **-** |
| └─ *BERT Inference* | *27.34 ms* | - | - | - |
| └─ *SNAP (BERT 제외 순수)* | *5.30 ms* | 4.64 ms | 2.36 ms | 0.1% |
| **Kiwi + phonology** | 2.55 ms | 0.84 ms | 50.28 ms | 0.1% |
| **g2pk** | 21.37 ms | 20.21 ms | 3.88 ms | 3.4% |

> **VITS 환경에서의 실질 추가 딜레이:**  
> VITS에 내장된 BERT Hidden State를 그대로 재활용하므로, VITS 환경에서 SNAP이 차지하는 추가적인 오버헤드는 **5.30 ms** (시스템 유휴 시 최소 **0.98 ms** 수준)에 불과합니다.

## 3. 주요 에러 패턴 분석 (g2pk 오류 요인)

숫자/영어가 완전히 제외된 순수한 한글 문장에서도 g2pk는 **1.2%의 명백한 발음 오류**를 발생시켰습니다. 이는 MeCab 형태소 분석기의 경계 인식 실패 및 과도한 예외 규칙 하드코딩에서 비롯된 것입니다.

### 3.1. 대표 에러 패턴 및 사례

1. **무리한 된소리화(경음화) 뇌절:**
   - 표준 발음법상 평음(예사소리)으로 읽어야 할 단어를 강제로 된소리로 발음하여 발음을 왜곡시킵니다.
     - `경례` ➔ `꼉녜` ❌
     - `조선` ➔ `쪼선` ❌
     - `관리` ➔ `꽐리` ❌
     - `사회주의` ➔ `싸회주의` ❌
     - `만든다` ➔ `만든따` ❌
     - `몇 개` ➔ `멷 깨` ❌
2. **연음 및 ㄴ첨가 누락:**
   - 명사 합성 결합부에서 ㄴ첨가가 일어나야 하나 일반 연음으로 처리하여 표준 발음 규정을 위반합니다.
     - `귀국 이듬해` ➔ `귀구 기듬해` ❌ (표준 발음은 [귀궁 니듬해]가 맞음)
3. **자음 첫소리가 없는 '의'의 발음 오류:**
   - 의미론의 '의'는 자음 첫소리가 없는 음절의 'ㅢ'이므로 [이]로 발음하는 것이 정확하지만, g2pk는 오발음을 냅니다.
     - `의미론` ➔ `늬미론` ❌ ([니미론]이 맞음)
4. **자음 탈락 및 형태소 붕괴:**
   - ㅂ받침이 생략되면서 뒤 단어의 초성을 오판하는 심각한 변환 오류입니다.
     - `사립 여학교` ➔ `사리 벼학꾜` ❌ (ㅂ받침 탈락 및 여➔벼 오독)

## 4. 최종 결론
- **SNAP의 분석 신뢰성 및 실시간성 입증:** 순수 한국어 문장에 대해서는 발음 왜곡율 0%, 실질 추가 딜레이 **5.30ms** (CPU 유휴 시 **0.98ms**)로 속도와 안정성을 완벽히 조화시켰습니다.
- **g2pk의 한계 명확:** 텍스트 전처리(영어/숫자)를 거치지 않은 가벼운 순수 한글 문장에서도 오독이 고정적으로 발생하여, 고음질 TTS Frontend로는 적합하지 않습니다.
