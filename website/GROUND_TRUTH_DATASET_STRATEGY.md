# Ground Truth 데이터셋 구축 전략 분석 및 의견

> **작성일**: 2026-07-28  
> **주제**: AI 생성 데이터셋의 신뢰성 확보 방안  
> **제안자**: 사용자  
> **평가**: 매우 우수한 과학적 접근법

---

## 📊 **제안 요약**

### 제안 1: Gemini + DeepSeek 교집합 활용
```
두 LLM의 공통 정답만 정답지로 사용
→ 단일 모델 특유의 환각/오류 제거
→ 데이터셋 순도 극대화
```

### 제안 2: 소수 사람 정답지 기반 프롬프트 보정
```
사람이 만든 정답지로 프롬프트 튜닝
→ 프롬프트가 사람 정답과 100% 일치하도록 보정
→ 방법론적 정당성 확보
```

### 통합 제안: 3단계 E2E 파이프라인
```
[1단계] Human Anchor 구축 (300~500건)
   ↓
[2단계] Prompt Calibration (프롬프트 튜닝)
   ↓
[3단계] Dual-LLM Consensus (교집합 추출)
```

## 🟢 **제안의 강점**

### 1. **제안 1: Gemini + DeepSeek 교집합 (Very High Precision)**

#### 장점:
```
✅ 단일 LLM 특유의 환각(Hallucination) 제거
   - Gemini의 특정 발음 규칙 오적용 제거
   - DeepSeek의 특정 패턴 오류 제거
   - 교집합만 사용 → 신뢰도 극대화

✅ 데이터셋 순도 극대화
   - Noise 제거율 높음
   - 벤치마크셋 신뢰도 상승
   - 논문 리뷰어 신뢰 확보

✅ 과학적 엄밀성
   - 다중 검증 메커니즘
   - 재현 가능성 높음
```

#### 고려할 점:
```
⚠️ 표기 규약 불일치로 인한 억울한 탈락
   - 띄어쓰기 차이: "세 번" vs "세번"
   - 구두점: "3번." vs "3번"
   - 조사 표기: "[의]" vs "[에]"
   - 숫자 음독: "3" → "삼" vs "쓰리"

⚠️ 교집합 크기 감소
   - 두 모델이 모두 맞아야 함
   - 데이터셋 규모 축소 가능
   - 다양성 감소 위험
```

#### 해결책:
```
✅ 강력한 텍스트 정규화 필수
   - 공백/특수문자 제거
   - 표준 표기 통일
   - 정규화 후 교집합 추출

✅ 정규화 규칙 명시
   - 논문에 정규화 규칙 상세 기술
   - 재현 가능성 확보
   - 리뷰어 신뢰 확보
```

---

### 2. **제안 2: 소수 사람 정답지 기반 프롬프트 보정 (Methodological Rigor)**

#### 장점:
```
✅ 방법론적 정당성 확보
   - 사람이 검증한 Anchor 데이터 기반
   - 프롬프트 튜닝의 과학적 근거 제시
   - 논문 리뷰어 신뢰 극대화

✅ 재현 가능성 확보
   - 프롬프트 공개 가능
   - 다른 연구자 재현 가능
   - 학술 커뮤니티 신뢰 확보

✅ 리뷰어 설득력
   - "AI에게 대충 시킨 데이터가 아님" 증명
   - 사람 검증 기반 고품질 생성 데이터 입증
   - 데이터셋 신뢰도 상승

✅ 프롬프트 품질 보증
   - 사람 정답과 100% 일치 달성
   - 프롬프트 신뢰도 극대화
   - 일관성 있는 데이터 생성
```

#### 고려할 점:
```
⚠️ 초기 투자 비용
   - 사람 정답지 작성 시간 필요 (300~500건)
   - 프롬프트 튜닝 반복 필요
   - 초기 리소스 투입 필요

⚠️ 프롬프트 과적합(Overfitting) 위험
   - 사람 정답지에만 맞춰진 프롬프트
   - 새로운 패턴에 대한 일반화 능력 저하 가능
   - 다양한 테스트 케이스로 검증 필요

⚠️ 사람 정답지의 편향
   - 소수 사람의 주관적 판단 반영
   - 특정 발음 규칙 선호 가능
   - 다양한 배경의 사람 참여 필요
```

#### 해결책:
```
✅ 다양한 배경의 사람 참여
   - 언어학자, 음성학자, 일반인 혼합
   - 지역 방언 고려
   - 다양한 관점 반영

✅ 프롬프트 일반화 검증
   - 사람 정답지 외 다양한 테스트 케이스
   - 새로운 패턴에 대한 성능 평가
   - 일반화 능력 입증

✅ 정답지 검증 프로세스
   - 다중 검증자 합의
   - 불일치 케이스 논의
   - 최종 정답 확정
```

### 3. **통합 제안: 3단계 E2E 파이프라인 (Best Practice)**

#### 구조:
```
[1단계: Human Anchor 구축]
├─ 목표: 300~500건의 고품질 사람 정답지
├─ 포함 패턴: 숫자, 기호, 연음, 경음화, 이의어 등
├─ 검증: 다중 검증자 합의
└─ 산출물: Gold Standard Anchor Dataset

[2단계: Prompt Calibration]
├─ 목표: 프롬프트가 사람 정답과 100% 일치
├─ 방법: 반복적 프롬프트 수정/보완
├─ 검증: Anchor 데이터셋에 대한 정확도 측정
└─ 산출물: Calibrated Prompts (DeepSeek + Gemini)

[3단계: Dual-LLM Consensus]
├─ 목표: 대량 데이터 생성 및 필터링
├─ 방법: 10,000건 이상 데이터 생성
├─ 필터링: 텍스트 정규화 후 교집합 추출
└─ 산출물: High-Quality E2E Test Dataset
```

#### 장점:
```
✅ 방법론적 정당성 + 데이터 순도 극대화
   - 사람 검증 기반 (정당성)
   - 다중 LLM 검증 (순도)
   - 최고 수준의 신뢰도

✅ 논문 리뷰어 설득력 극대화
   - 과학적 엄밀성 입증
   - 재현 가능성 확보
   - 데이터셋 신뢰도 상승

✅ 학술 커뮤니티 신뢰 확보
   - 투명한 방법론
   - 공개 가능한 프롬프트
   - 다른 연구자 재현 가능

✅ 데이터셋 품질 극대화
   - 높은 정확도 (사람 검증)
   - 높은 순도 (다중 LLM 검증)
   - 높은 다양성 (대량 데이터)
```

## 📋 **구현 로드맵**

### Phase 1: Human Anchor 구축 (2-3주)
```
1. 정답지 작성 가이드라인 수립
   - 발음 규칙 정의
   - 표기 규약 통일
   - 예시 제공

2. 다양한 패턴 문장 선정
   - 숫자: 3번, 2020, 3/4 등
   - 기호: 시간, 날짜, 비율 등
   - 연음/경음화: 발음 변화 케이스
   - 이의어: 동철이음이의어
   - 언어별: 한국어, 영어, 일본어

3. 사람 정답지 작성
   - 3-5명의 검증자 참여
   - 각자 독립적으로 작성
   - 불일치 케이스 논의 및 합의

4. 최종 정답지 확정
   - 다중 검증자 합의 기반
   - 정규화 규칙 적용
   - 문서화
```

### Phase 2: Prompt Calibration (2-3주)
```
1. 초기 프롬프트 작성
   - DeepSeek용 프롬프트
   - Gemini용 프롬프트
   - Few-shot 예시 포함

2. Anchor 데이터셋 검증
   - 300~500건 테스트
   - 정확도 측정
   - 오류 분석

3. 프롬프트 반복 수정
   - 오류 패턴 분석
   - 프롬프트 개선
   - Few-shot 예시 추가/수정
   - 반복 검증

4. 100% 일치 달성
   - Anchor 데이터셋에 대해 100% 정확도 달성
   - 프롬프트 최종 확정
   - 문서화
```

### Phase 3: Dual-LLM Consensus (1-2주)
```
1. 대량 데이터 생성
   - 10,000건 이상 문장 준비
   - DeepSeek 생성
   - Gemini 생성

2. 텍스트 정규화
   - 공백/특수문자 제거
   - 표준 표기 통일
   - 정규화 규칙 적용

3. 교집합 추출
   - 두 LLM 결과 비교
   - 100% 일치하는 문장만 선별
   - 최종 데이터셋 구성

4. 최종 검증
   - 데이터셋 통계 분석
   - 패턴 다양성 확인
   - 품질 평가
```

## 💡 **추가 권장사항**

### 1. **정규화 규칙 명시**
```
논문에 정규화 규칙을 상세히 기술:
- 공백 제거 규칙
- 특수문자 처리 규칙
- 표준 표기 통일 규칙
- 예시 포함

→ 재현 가능성 극대화
```

```
논문 부록에 최종 프롬프트 공개:
- DeepSeek 프롬프트
- Gemini 프롬프트
- Few-shot 예시

→ 학술 커뮤니티 신뢰 확보
```

### 3. **오류 분석**
```
교집합에서 제외된 데이터 분석:
- 제외 이유 분류
- 표기 규약 불일치 비율
- 실제 오류 비율
- 패턴별 분석

→ 데이터셋 한계 명시
```

### 4. **다양성 검증**
```
최종 데이터셋의 다양성 검증:
- 패턴 분포 분석
- 언어별 분포 분석
- 길이 분포 분석
- 복잡도 분석

→ 데이터셋 대표성 입증
```
